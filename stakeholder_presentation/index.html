07Trust & safeguards

Useful AI needs visible boundaries.

An agent may reason and propose; approved services enforce access, validate actions, and verify results.

▤Grounded in approved schema

SQL generation uses live metadata and approved Gold tables; unknown or unsafe statements are rejected.

✓Human review before execution

Analysts inspect generated SQL and explicitly approve a policy query before it runs.

◉Credentials stay server-side

The model does not receive Databricks credentials or connect to the warehouse directly.

↻Actions pass through application rules

Supported ticket updates are checked and recorded by the backend; approval remains with the user.

Enterprise target · production controls

Bound every tool call. Verify every answer.

These are deployment gates to add and validate; the current POC is not represented as production-hardened.

Identity & data access

Corporate SSO, per-user authorization, least privilege, row/column controls, and sensitive-data masking.

Agent & tool guardrails

Allowlisted tools, typed inputs, bounded steps/time, injection-resistant data handling, and approval for writes.

Ground truth & evaluation

Versioned golden questions with expected SQL/results and tolerances; test correctness, permissions, refusals, and adversarial cases.

Audit & operations

Trace user, model/prompt version, tool calls, approval, and execution; redact secrets, monitor quality/latency/cost, and support rollback.

Release gate: regression evaluation after model, prompt, schema, or tool changes · human sign-off for consequential actions · retention by policy.
